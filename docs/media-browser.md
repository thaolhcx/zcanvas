# Media browser

The canvas UI for [issue #19](https://github.com/thaolhcx/zcanvas/issues/19), part of [#11](https://github.com/thaolhcx/zcanvas/issues/11). It follows the approved prototype in [`design/media-browser/`](design/media-browser) and the [design notes](design/media-browser/design-notes.md), and uses the asset APIs in [`asset-platform.md`](asset-platform.md). The prototype's inline script is not used.

Code is in [`web/src/media/`](../web/src/media). Templates and Media share [`BrowserShell.tsx`](../web/src/media/BrowserShell.tsx).

## Where it opens

- The **Media** button in the tool rail (browse mode).
- **Choose from library** in an asset field, and **Choose another file** on an Asset node whose file was deleted (pick mode). Pick mode shows only the kinds that the node's connected inputs accept, uses radio buttons and ends with **Use selected …**.

Browsing never waits for search by meaning.                                                                                                                                                                                                                                                                                                         |

The details player takes the same slot. Scroll-out, closing, switching space and a hidden page stop and release the player.                                                                                                                        |
| Selection          | Checkboxes keep selections across filters and searches. The footer shows "N selected · M outside this filter", **Clear selection** and **Add N items to canvas**. Choose another file." and a picker button. Runs report `INPUT_REQUIRED` for such nodes.                                                                                                                 |

Upload, rename and delete are hidden.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |

## Differences from the issue spec

- **Keyboard preview** uses a focusable Play button on each video and audio card (Enter or Space), not Enter on the card itself. Enter on the card opens details, as it does for every other card.
- **Pick mode** limits kinds by the Asset node's connections. The `input.asset` param is declared as `image` but the node outputs any media, so locking to the param's kind would hide valid video and audio.
- **Cross-space media** can be browsed, previewed and downloaded, but Add, drag and pick are disabled with a note. The run path only accepts assets from the canvas's space (#16).
- **FPS evidence** for the 500-asset scroll comes from a `requestAnimationFrame` counter in the test, not the `?debug=1` panel, which sits under the browser overlay.
- **Details on narrow screens** (≤ 1180 px) float over the grid instead of squeezing it to one column, as the prototype does below 760 px.

## Tests and evidence

- Unit ([`web/test/media.test.ts`](../web/test/media.test.ts)): selection across filters and clearing rules, pick mode, removal and access loss; placement without overlap and a batch that one Undo removes; the preview controller (delay, audio, one player, dragging, scrolling, reduced motion, release); the search badge.
- E2E ([`e2e/media.spec.ts`](../e2e/media.spec.ts), [`e2e/media-performance.spec.ts`](../e2e/media-performance.spec.ts)), run with both `STORAGE_DRIVER=local` and `STORAGE_DRIVER=s3` (MinIO):
  1. Upload goes into the canvas's team space and the configured storage driver. The card is dragged onto an Edit image input, which creates a connected Asset node, and the run uses that asset.
  2. Three selected files across a kind filter and a search become three nodes without overlap, one Undo removes them, and switching space clears the selection. Covers viewer roles and the Stock unavailable state.
  3. Rename keeps references, a usage row locates the node, delete lists the affected node, the node shows **Deleted file**, the run reports `INPUT_REQUIRED`, and the picker opens from the node.
  4. Prompt, reference name, model and settings stay as saved after the source prompt is edited.
  5. Hover video starts after 400 ms and not before, is muted, and stops on leave; audio is silent on hover and plays on Play; one player at a time, including the details player; keyboard Play; a hidden page and closing release players; reduced motion turns off hover playback.
  6. Touch Play on a `hasTouch` context.
  7. Search by meaning (`hybrid`, `ok` with the local model) and name-only fallback (`EMBEDDING_PROVIDER=none` shows **Name matches only**), then revoked membership: the API returns `404` and the browser shows the access message with no cards or selection.
  8. 500 assets: [`evidence/media-browser-scroll.json`](evidence/media-browser-scroll.json). 59–60 FPS against a 60 FPS baseline, at most 40 mounted cards and no media elements while scrolling.
- Screenshots next to the prototype at 1440 and 1024 px wide: [`evidence/media-browser/`](evidence/media-browser).

## Limits

- Headless Chromium here has no H.264 decoder, so the E2E checks that players mount, are muted and are released, not decoded frames. The details-player check fires the player's own `play` event.
- The scroll check needs an idle server: right after uploads that leave preview and indexing jobs running it measured 48–53 FPS in this container, so it runs first in its own file.
- The existing 128-node checks still pass at the same rates as `main` here. `pans a 128-node canvas … four selected edges signal` sometimes records a single 100 ms frame on both branches.
